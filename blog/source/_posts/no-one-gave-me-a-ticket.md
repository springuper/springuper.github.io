最近这一年多，我接连碰到几件让我颇为感慨的事。但在讲它们之前，我得先交代立场，因为这篇文章的结论和我的立场高度相关。

**我是一个偏内归因的人，而且这一路走得还算顺。** 遇到问题，我的第一反应通常是"我自己还能做什么"。这种反应方式在我身上一直得到正反馈，所以我对它是有偏爱的。

正因为如此，我说的每一句话都得先打个折扣——**这是我的路径，不是所有人的路径。**

而且我更该警惕的是：我的路径里有很多东西并不是我争取来的。我加入现在这家公司的时候，中国团队正在快速扩张，**管理岗是增长本身创造出来的**；在上一家公司，我赶上了行业打得最凶的那几年；我能进入技术委员会，**不是我自己挤进去的，是我的老板替我争取的**。这些都是顺风，它们只是恰好在那里。

所以写这篇我给自己定了两条规矩：**一是别把自己的路径当成标准答案；二是别把那些我恰好没遇上的障碍，轻描淡写成"借口"。**

<!--more-->

## 我听到的那些说法

最近一年多，我看到一个挺反讽的现象：AI 编程工具让团队里大部分人的产出都有了不错的提升，但人与人之间的差距没有缩小，反而在拉大。

有人明显原地踏步，个别甚至有所回落。这些同事身上有些很具体的信号：不主动同步进展，一件事推一下动一下。坐下来聊原因，听到的说法大致是这几类：

- 需求连个工单都没有，没法开工
- 海外团队那边的情况，我怎么可能知道
- 有时差在，重要的事情本来就轮不到我；既然不重要，那也不着急

这些说法单拎出来，每一条都不算离谱。但合在一起，就构成了一个完整的、自洽的、几乎无法反驳的世界模型：**问题都在外面，我没什么可做的。**

还有一种情形是发展受阻：直接汇报的老板总在换，之前投入的大项目又没做出什么业务价值，最后的结论是"很不爽，但也没办法"。

再有一种是晋升落差：身边不少同事这几年陆续都有了晋升，自己却一直没动静，于是觉得不太公平，也比较苦闷。这位同事的情况要更复杂一些——他入职后长期做的是相对独立、偏非核心的业务，而团队更缺的是能推动跨部门协作的人，所以那类机会分配时没有优先给他。值得一提的是，他的状态在一点点改善。

不瞒你说，这几种状态我自己身上也出现过，只是程度和时长不同。所以下面这些分析里，也包括我自己那一份。

## 那些没有工单的事

我想先接住第一条："没有工单"是真的。但对我来说，它是**起点**，不是**结论**。

因为在同一家公司里，我做过的最重要的那些事，几乎都没有工单。

做播放器那几年，我主导了 web 和 OTT 播放器的几乎所有重点项目：把播放方案换成 Hls.js 重写一遍、接入 DRM 让更多优质内容能播、搭起监控把可观测性补上、写一个 JS bridge 让原生容器里的 HTML5 更好用，还用 CDP 做了一个内部调试工具。

**没有一件是别人开给我的工单。** 都是我自己判断"这里需要有人做"，然后去做了。

更典型的是另一件事：让中国团队和美国的资深管理者之间真正协作起来，曾经是我职责里最重的一块。这件事更不会有人给我开工单，而且它一点都不轻松——我在自己的介绍里写过一句：honestly, it's incredibly challenging。

**所以我听到"没有工单就没法开工"的时候，第一反应不是反驳，是理解**——那种感觉我熟悉。差别只在于，我把"没有工单"当成了一块需要我自己去填的空白，而不是一条到此为止的终止线。

但这里我必须补一句反面的话，因为这是我在跟同事谈话时最容易忽略的一点：

**很多时候，自己补工单等于替别人扛了职责，却没有对应的权限。** 你去猜需求，猜对了没人记得，猜错了是你的理解偏差。这**不是**个体靠"更主动一点"就能解决的问题。

所以我的判断标准是：**看这件事做完之后，能不能留下可见的东西。** 如果它能换来一点信任额度、能让别人看见你在解决什么问题，那就值得做；如果它只是让你在没有权限的情况下承担了别人的责任，那就不值得——**那种情形下该做的是把责任还回去，而不是自己扛。**

这个区分很重要。**把"缺工单"无差别地当成个人执行力问题，是管理者的偷懒。**

## 那堵墙，和墙下的人

外归因和向内归因不是我的发明。Rotter 在 1966 年提出"控制点"（Locus of Control）：内控型的人倾向于认为结果取决于自己的行为，外控型倾向于认为取决于运气、环境和他人。

这个区分最有价值的地方不是道德评价，而是它能预测下一步行动。**如果你认定问题在外面，逻辑上的必然结论就是"我无需改变"**——短期内非常舒服，它保护了自尊，也省去了面对自身短板的痛苦。但代价是长久的：**你把自己人生的遥控器交了出去。**

有一句总结我很认同：

> 外归因最省力：出事先找替罪羊，过错全推给外界，短期心理平衡，不用跟自己的短处较劲。但代价是永久丧失进化的可能——既然问题都在外面，自己自然无需改变。
> ——知乎答主[「起风了」](https://www.zhihu.com/question/525200257/answer/2072798775140160515)

但比这更重要的一件事是：**有一类"外归因"根本不是态度问题，而是习得性无助。**

塞利格曼的经典实验说明，当一个个体反复经历"无论怎么努力都无法改变结果"之后，他会彻底放弃尝试——哪怕后来环境变了、机会来了，他也不动了。

放到职场里就很清楚了：如果他主动提的方案被驳回、多做的额外工作没被看见、出了问题还要独自担责，那么"不主动"就是他学到的、**最理性的自我保护**。

这一类不是靠讲道理能谈通的。你需要先给他一次完整的正向闭环：

```
  ① 主动做了一件事
       │
       ▼
  ② 这件事被看见了
       │
       ▼
  ③ 因此得到了实际回报
       │
       └────────────────► 重建"我的行为和结果有关"这个信念
```

反过来，如果他已经形成了这个闭环的负面版本，那就很难拆——因为它每转一圈都在自我加固：

```
  ① 觉得「反正不会给我重要任务」
       │
       │ 于是不全力投入
       ▼
  ② 确实拿不出重要产出
       │
       │ 于是更确信
       ▼
  ③ 更确信「不会给我重要任务」
       │
       └────────────────► 回到 ①，闭环成立
```

这个环一旦转起来，别人再想给机会也接不住了。**它和"时差"没有关系，它是两边共同造成的。**

## 我的盲区

写到这里我得停一下，因为上面这些话，由一个偏内归因的管理者说出来，特别容易变味。

**我最大的盲区恰恰是：因为我自己验证过"向内归因有用"，我会不自觉地默认别人也应该、也能够做到。**

用统计的话说，**我的样本量是 1**。而我恰好没遇到过的那些障碍——时区、语言、评价体系的偏好、项目怎么分配——在我这儿不存在，于是很容易被我低估成"借口"。

社会心理学里有个概念叫**基本归因错误**：我们解释别人的行为时，倾向于高估个人特质，低估情境的作用。换成管理场景就是——看到下属不主动，立刻归因成"他就是不积极"，而很少去问：是不是流程里缺了关键一环？是不是跨时区的信息通道我没建？是不是我在派活时有偏好？

这和我之前在 [Just Culture](https://springuper.github.io/just-culture/) 里写的是同一件事：出了状况，先问"哪里出了问题"，而不是"谁出了问题"。

**而且我自己的经历就是证据：我能进技术委员会，是我的老板替我争取的。门是别人给我打开的。**

所以我这一节写给管理者看，不是摆姿态——是因为我知道**有人替你开门**是什么感觉，也就知道该替谁开门：

- 他说没有工单就没法开发——那么是谁的责任把需求变成工单？这是我的流程问题
- 他说跨时区的信息拿不到——那么是谁该建这条信息通道？这是我该解决的
- 那些推动跨部门项目的机会始终没轮到他——那么是不是我在派活时的偏好，把他锁死在了一个很难被看见的位置上？

但要区分卡点的类型，因为对策完全不同：

```
                  他没产出，看是哪一类卡点
                              │
      ┌─────────────────┬─────┴───────────┬─────────────┐
      ▼                 ▼                 ▼             ▼
  能力不够          意愿不足          信息不够      资源不够
 培训 / 结对      谈动机与期望        补上下文       给资源
  调整岗位       胜任感 · 自主性     信息通道       清障碍
                     归属感
```

其中「意愿不足」这一类，自我决定理论说得最清楚：胜任感（我做得了吗）、自主性（这是我的选择吗）、归属感（我和团队有关系吗），三者缺一不可。

## 那场谈话该怎么说

上面这些还是原则。真正难的是坐下来开口。我自己试过有用的一组问题是这样的——**把"你为什么不主动"换成具体的提问**：

- 最近哪件事让你觉得卡住了？当时你想做什么？
- 你试过什么？结果怎么样？
- 如果这件事由你定，你会怎么排优先级？
- 我能帮你清掉哪个障碍？

这组问题的用意不是套话，而是**把一次关于态度的审判，变成一次关于障碍的共谋。**

至于"试多久算够"，我的做法是：**先把环境侧的三件事做完**——流程（工单该谁负责）、信息（跨时区通道）、机会（派活有没有偏好）。这三件事都有明确的负责人，也就是我。**然后给一个明确的观察周期**，我的经验是一个季度。如果环境和激励都到位了、行为仍然没有变化，那才进入绩效讨论。

**这个顺序不能颠倒。先修环境再谈人，不是因为管理者要宽容，而是因为不这样做，你根本分不清问题在人还是在环境。**

而如果都做过了依然如此，那确实该直面——原因很简单：**团队里其他人看得见。** 我在 [Fire Fast](https://springuper.github.io/fire-fast/) 里写过一句"容忍低绩效者是对大多数人的惩罚"。同样地，如果一个团队慢慢默认了"归因于外是可以被接受的"，这种默认会像传染病一样稀释掉整个团队的进取心。这比某一个人的产出下滑要严重得多。

## 我见过的晋升者

我做了这么多年管理，有一件事是我反复观察到的：**我见过的晋升者，多数在行为上是主动的、担责的、会主动同步的。**

这句话在我文章里最容易被误读成"向内归因所以晋升"。所以我要先把三种可能的反驳说出来，因为它们都成立：

- **反向因果**：也可能不是"向内 → 晋升"，而是"晋升 → 向内"。心理学里的自我服务偏差说，人会把自己的成功归因于内、把失败归因于外。那么晋升带来的掌控感，本身就会让人显得更内控
- **缺对照组**：我并没有统计过没晋升的人里内归因的比例。如果大部分人本来就偏内归因，那这个观察的相关性其实很弱
- **叙事偏误**：用"心态"解释结果，是因为心态是个好讲的故事。真实的晋升变量常常是项目分配、时机和老板偏好

**所以我不敢把它说成因果。我能说的是行为，以及我在行为背后理解的机制。**

不过有一个反驳是站不住的，值得写出来：自我服务偏差说的是"**成功**向内、**失败**向外"。而我在那些晋升者身上看到的最明显的东西，不是他们怎么解释自己的成功，而是**项目不顺的时候他们怎么反应**。这一点，反向因果解释不了。

另外，我承认确实有一部分人上位靠的是亮点项目和顺风局——**这部分不是主流，但它真实存在，也不该被含糊过去。** 而且有意思的是，这两件事往往不是竞争关系：**亮点项目本身通常是争来的**，主动的人更容易被放进好项目里。所以"顺风局"在相当程度上是内归因的结果之一。

但也有纯运气的部分——刚好组里缺人、刚好老板信任、刚好赶上一个好赛道。这部分不可复制、不可控，承认它，后面的建议才诚实。

## 三条路都成立

回到"晋升落差"那一位。有一件事我们必须格外小心，因为**它可能是真的**：

评价体系确实会青睐某些能力（比如沟通、跨部门影响力），而冷落另一些能力（比如把非核心的服务做深做透）——**这对当事人来说，确实构成一种结构性的不利。承认这一点，是讨论的前提。**

```
 一事当前，原因都是真实存在的
 ├────────────────────────────────┼────────────────────────┤
 │ 环境 · 他人 · 时机             │ 我能改变的部分         │
 └────────────────────────────────┴────────────────────────┘
   承认它，但不必在这里反复消耗      精力投在这里才有回报
```

但关键在于，不要卡在"不公平"这个结论上不动。面对同一个不公平，**三条路都成立**：

1. **补短板**：理解体系看重什么，然后去补（前面那位同事正在做的，正是这件事）
2. **换赛道**：清醒地判断"我不想成为那种人"，然后去一个真正看重自己优势的环境
3. **接受现状，但停止情绪消耗**：承认代价，也接受代价

三条路都可以，唯独"持续苦闷且不行动"不可取。前面"发展受阻"和"晋升落差"那两种情形的差别恰恰在这里：同样委屈，一个停在"不爽但没办法"，一个已经开始动了。

## 我自己在练的几件事

最后这些是我自己在用的，说出来供参考，不是给谁的建议。

**第一，把停下来的注意力分个类。** 遇到事情我会在心里分三栏：

```
┌──────────────┬────────────────┬──────────────────┐
│ 我能控制     │ 我能影响       │ 我控制不了       │
├──────────────┼────────────────┼──────────────────┤
│ 我的投入     │ 老板的预期     │ 时差             │
│ 我的沟通频率 │ 需求的优先级   │ 人事变动         │
│ 我的技能     │ 跨团队协作方式 │ 公司战略         │
├──────────────┼────────────────┼──────────────────┤
│ 全力以赴     │ 持续经营       │ 接受，不反复咀嚼 │
└──────────────┴────────────────┴──────────────────┘
```

**最常见的错误，是把第一栏和第二栏的事，误判成了第三栏。**

**第二，主动同步。** 这是我做下来性价比最高的一件事。每周更新一次进展、卡点和下一步，写下你遇到的困难，也写下你打算怎么处理。在跨时区的团队里，**可见度本身就是产出的一部分**。很多人把汇报当负担，其实它是最低成本的存在感投资。

**第三，从约束里挑一件小事做完。** 不要等条件齐全才动手。缺工单，就先写一版草稿需求；跨时区信息拿不到，就先整理一份已知信息发出去请人补充。**完成一件小事带来的信任额度，比十次抱怨管用。**

**第四，把职业锚点放在成果上，而不是放在某个人身上。** 老板会走，你在流程文档、项目成果、可迁移能力上留下的痕迹不会走。那位换了好几任老板的同事，履历上写的不是"我服务过好几位老板"，而是"我做成过 N 件事"。

## 结语

回到开头那个反讽的现象：这几年 AI 把每个人的产出杠杆都放大了，按理说大家应该一起水涨船高，但差距反而在拉大。

我现在越来越倾向于认为，差距的主要来源不是"会不会写代码"，而是**你怎么解释自己的处境，以及你因此做了什么**。工具可以让一个主动的人产出翻倍，也可以让一个被动的人继续原地不动——**它只是放大了你原本的样子。**

最后想说的是，归因方式不是一种道德评价。偏内归因的人并不比偏外归因的人更高尚，这只是一个**效率问题**：它决定你把有限的精力投向哪里。

而它最终给你的回报，也不只是升职加薪。向内归因真正让人获得的东西是——**无论环境怎么变，你手里始终有得选。**

当然，这句话由一个走得还算顺的人说出来，本身就带着立场的折扣。**如果你觉得我说得轻巧，那是合理的怀疑。** 我能做的，也只是尽量把自己那点顺风、那扇别人替我开的门，和这个结论一起摆出来。
